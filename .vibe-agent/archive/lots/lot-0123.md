# Lot #123 — Ouverture en artefact

- epic : Dashboard usage · clos : 2026-07-29 · commit : ecd9478 · session : inconnue · us : —
- verify : `node test/run-tests.js` → OK (2054 OK · 0 échec)

## Objectif

`/pmz:dashboard` ne produisait que `.vibe-agent/dashboard.html`, à ouvrir soi-même dans un
navigateur. Faire que la commande publie aussi la page directement en artefact, HTML toujours
autonome (zéro réseau), sans introduire un second gabarit qui pourrait diverger du premier.

## Décisions (et pourquoi)

- **Contenu factorisé, pas dupliqué** : `buildContent()` calcule une fois titre/synthèse/corps/
  pied de page ; `buildHtml()` (document complet) et `buildArtifactHtml()` (variante) rendent
  la même donnée différemment. Éviter exactement le piège nommé dans le handoff du lot #122
  (« il faudra une variante de rendu, pas un second gabarit divergent »).
- **La feuille de style n'est pas recopiée** : `extractStyle()` la lit dans le même
  `templates/dashboard.html` via le bloc `<style>…</style>` existant — une seule source, la
  variante artefact ne peut pas dériver visuellement du document complet.
- **Chemin de l'artefact dérivé de `--out`** (`artifactOutPath()`, suffixe `.artifact.html`)
  plutôt qu'un nom fixe indépendant : toujours à côté du document qu'il complète, jamais à sa
  place, même avec `--out` personnalisé.
- **Même politique fail-open que le document complet** : écriture de l'artefact dans son propre
  `try/catch`, `written:false` en cas d'échec, jamais un exit non nul. `--stdout` ne produit
  ni document ni artefact (l'appelant demande explicitement le flux HTML brut).
- **`Artifact` ajouté aux `allowed-tools` de `commands/dashboard.md`**, pas rendu implicite :
  la commande dit explicitement quand l'outil n'est pas disponible plutôt que de rester muette.
- **Pas de `<title>` dans la variante** : un artefact ne peut pas porter de `<head>` fourni par
  l'appelant (balise interdite par l'outil de publication) ; le titre reste dans le texte de la
  commande, pas dans le fragment HTML.
