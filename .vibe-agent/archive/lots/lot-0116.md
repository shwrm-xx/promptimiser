# Lot #116 — Prescription RTK dans la consigne injectée

- epic : Bridge RTK · clos : 2026-07-29 · commit : 2374c4b
- verify : `node test/run-tests.js` → OK (1946 OK / 0 échec)

## Objectif

Quand RTK est détecté, la consigne injectée par PMZ au démarrage (`rtkStartupLine`, lot #86) devait
prescrire les équivalents `rtk` (grep, read, git, ls, find) au lieu des commandes nues, en réutilisant
le texte de `rtk init` plutôt qu'un texte inventé ; silence total si RTK absent ; extension de
`rtkStartupLine`, pas de brique neuve ; tests verts.

## Décisions (et pourquoi)

- **Texte de la prescription sourcé depuis une exécution réelle de `rtk init` (v0.43.0) en bac à
  sable**, pas depuis la doc `--help` (qui ne montre que les flags, jamais le corps réellement
  injecté dans `CLAUDE.md`). Les 5 commandes et leurs chiffres de gain (`rtk grep`/`rtk read`/
  `rtk git`/`rtk ls`/`rtk find`, 60-80%) sont repris verbatim de ce corps (sections « Files &
  Search » + « Git »).
- **Prescription ajoutée uniquement sur `present-inactive`/`active`**, pas sur `conflict`/
  `incompatible` : ces deux derniers états signifient un binaire non fiable (conflit tiers non
  coordonné ou `--version` en échec) — prescrire son usage y serait trompeur. `absent` reste
  silencieux, inchangé.
- **Prescription valable indépendamment de l'activation du bridge PMZ** : le bridge (rewrite
  automatique des appels Bash) est une notion distincte de la prescription (dire à Claude de
  préfixer lui-même ses commandes) — les outils dédiés Read/Grep/Glob ne passent de toute façon
  jamais par le bridge Bash, donc la prescription reste utile même bridge actif.
- **Constante `RTK_PRESCRIPTION` exportée** plutôt qu'inline dans `rtkStartupLine`, pour que les
  tests vérifient la présence du texte réel sans dupliquer sa formulation.

## Vérifié

- Suite complète : 1946 OK / 0 échec (1941 + 5 nouveaux cas du lot).
- `rtkStartupLine({state:'present-inactive'})` et `({state:'active'})` contiennent bien
  `RTK_PRESCRIPTION` ; `conflict`/`incompatible` ne le contiennent pas ; `absent`/`null` restent
  `null` (inchangé, régression testée).
- Les 5 tokens `rtk grep`/`rtk read`/`rtk git`/`rtk ls`/`rtk find` sont bien cités verbatim dans
  `RTK_PRESCRIPTION` (assertion dédiée).

## Non vérifié

- **`rtk discover` montrant la couverture qui monte** (dernier critère du scope) : nécessiterait un
  usage prolongé en session réelle où Claude préfixe effectivement ses commandes bash suite à cette
  prescription, puis un `rtk discover` constatant la hausse — hors portée d'une vérification
  immédiate en bac à sable, dépend du comportement observé sur de futures sessions.
