# Lot #106 — Gabarit US enrichi + génération du fichier

- epic : Formalisation US · clos : 2026-07-28 · commit : 06fba38 · session : inconnue
- verify : `node test/run-tests.js` → OK · coût : ~17k tokens de sortie

## Objectif

Deuxième lot de l'epic. Le champ `us` (lot #101) n'avait qu'une porte d'entrée, `add --us`, et
elle supposait l'US **déjà rédigée** : un lot créé sans US ne pouvait en recevoir une qu'en
éditant `backlog.json` à la main, hors gardes. Ajouter une commande `us` (lecture, génération
depuis un gabarit revu, rattachement) et enrichir le gabarit.

## Décisions (et pourquoi)

- **Trois régimes calqués sur `verify`** (sans flag = lecture, `--new`, `--set`) : forme déjà
  connue du CLI, aucun vocabulaire nouveau à apprendre.
- **Lecture = pointeur seul, le fichier US n'est jamais ouvert** : la frontière du lot #101
  (pointeur, jamais le contenu) vaut aussi pour la sortie du CLI — coût de contexte nul.
- **Chemin conventionnel sans slug de titre** (`docs/us/US-<id>.md`) : un titre de lot bouge
  (renommage, reformulation), le chemin dérivé resterait faux ; l'id, lui, est immuable.
  Convention alignée sur celle déjà documentée pour `--us`, pas une nouvelle.
- **Écriture et rattachement indissociables** (`createUsFile`) : un fichier posé sans pointeur
  serait invisible du backlog, un pointeur sans fichier est refusé par `setUs`.
- **Refus doux si le fichier existe** : la commande *génère*, elle n'écrase jamais une US
  rédigée. Le refus propose `--set` comme issue — sinon la commande était un cul-de-sac pour un
  lot dont l'US existe mais n'est pas rattachée.
- **`--set` ajouté hors scope littéral** (le lot ne demandait que `--new`) : assumé et signalé à
  l'utilisateur, justifié par le cul-de-sac ci-dessus. Symétrie exacte de `verify --set`.
- **Lot clos = lecture seule** : une US écrite après la clôture ne gouverne plus rien ; la
  consultation reste légitime, donc seule l'écriture est refusée.
- **Gabarit résolu depuis le code** (`lib/backlog.js` → `../templates/us-template.md`), jamais
  depuis le dépôt utilisateur : il part tel quel dans les deux canaux d'install.
- **Gabarit enrichi mais borné (< 60 lignes, borne écrite dans le fichier)** : le coût de
  relecture est assumé (arbitrage utilisateur), mais un dépassement signale un lot à redécouper,
  pas une US à étirer.
