# Lot #127 — Dépôt ajoutable en marketplace

- epic : Diffusion plugin · clos : 2026-07-29 · commits : 27516f7 + a3df852 · session : « compatibilité marketplace »
- verify : `node test/run-tests.js` → OK (2175 OK · 0 échec) · coût : non mesuré

## Objectif

Rendre le dépôt directement ajoutable comme marketplace Claude Code :
`claude plugin marketplace add shwrm-xx/promptimiser` doit suffire.

## Décisions (et pourquoi)

- **Catalogue committé sur `main`, plugin tiré de la branche d'artefact.** Trois contraintes du
  format plugin, vérifiées contre la doc officielle (CLI 2.1.215), ferment les autres options :
  (1) le catalogue n'est lu qu'à `.claude-plugin/marketplace.json`, **à la racine** et sur la
  **branche par défaut** ; (2) une branche ne s'ajoute qu'avec l'URL git complète + **`#ref`**, la
  forme `owner/repo@ref` n'existe pas ; (3) le plugin est **copié dans un cache** à l'install et ne
  peut référencer aucun fichier hors de son dossier. Donc une source relative `./promptimizer` sur
  `main` serait cassée : `skills/promptimizer/` vit hors de `promptimizer/`, et les chemins
  `~/.claude/promptimizer` des `.md` ne sont réécrits en `${CLAUDE_PLUGIN_ROOT}` qu'au build.
  D'où la source **`git-subdir`** (`path` = `promptimizer`, `ref` = `plugin-release`) : `main` reste
  le miroir plat source, aucun artefact de build n'y entre, et la commande utilisateur est unique.
- **Alternative écartée : restructurer la source au format plugin natif** (déplacer le skill sous
  `promptimizer/`, écrire `${CLAUDE_PLUGIN_ROOT}` dans la source et inverser la réécriture côté
  install manuelle). Plus direct à l'usage, mais touche le canal manuel et exposerait
  `statusline.md` — commande cassée en plugin — dans le plugin livré. Reste ouvert si le canal
  manuel est un jour retiré.
- **Pas de `version` dans l'entrée marketplace** : la doc précise qu'un `version` posé là *ou* dans
  `plugin.json` épingle le plugin. En le laissant au seul `plugin.json` (aligné sur `VERSION` par
  `build-plugin.js`), la release garde une source de vérité unique et le catalogue de `main` n'est
  jamais à retoucher.
- **Deux catalogues homonymes assumés** : la branche garde le sien (fallback historique), même nom
  `pmz-marketplace`. Claude Code n'enregistre qu'une marketplace par nom → ajouter l'un remplace
  l'autre. Vu comme deux chemins vers la même marketplace plutôt que comme un conflit ; le canal
  `main` est documenté comme recommandé. À revoir si la confusion se manifeste à l'usage.
- **Garde-fou plutôt que génération** : le catalogue duplique 5 champs de `plugin.json`
  (name/description/license/homepage/repository). Plutôt que de le générer — il doit être statique
  et committé — la section de test B127 refuse toute divergence, dans l'esprit de `REQUIRED_COMMANDS`.

## Dette restante

- `lib/messages.js:58` et `:461` portent en dur `~/.claude/promptimizer` dans des consignes
  injectées — faux en canal plugin. Le motif de correction existe déjà
  (`PMZ_BASE = CLAUDE_PLUGIN_ROOT || '~/.claude/promptimizer'` dans `scripts/backlog.js` et
  `scripts/close-batch.js`). Défaut **préexistant**, repéré ici, laissé hors périmètre et spawné
  en tâche séparée.
- `build-plugin.js` ne réécrit que les `.md` (`rewriteMdInDir`) : tout chemin manuel écrit dans du
  JS échappe au filet. Aucun garde-fou n'interdit d'en réintroduire.
- Publier une release reste en deux gestes non liés : bumper `VERSION`/committer, puis
  `publish-plugin.js --push`. Rien ne signale un catalogue servant une branche périmée — c'est
  exactement le trou qui avait laissé `plugin-release` figée en 2.0.1 pendant deux jours.
